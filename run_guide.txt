推荐：统一管理三个常驻服务
========================================
以下命令都在项目根目录执行：

cd /srv/Fuda_CVPreject

# 启动三个服务（已有同名 tmux 会话时会跳过）
bash scripts/start.sh

# 查看三个服务的 tmux、端口和健康状态
bash scripts/status.sh

# 停止三个服务（需要输入 yes 确认）
bash scripts/stop.sh

# 停止三个服务且不再询问
bash scripts/stop.sh -y

# 强制重启三个服务
bash scripts/start.sh --force

# 从旧五服务版本首次升级时，推荐先执行 stop.sh；它会同时清理旧的
# guard_room / security_vlm tmux。若直接启动，普通模式会拒绝重复运行，
# --force 模式会先清理旧会话再启动。

统一启动后只创建以下三个 tmux 会话：
- unified_frontend：前端，端口 3000
- unified_backend：统一后端，端口 5000
- aivision：全部视觉检测业务，端口 7862

Guard Room 和 Security VLM 已经直接由 AiVision 进程承载：
- 保安行为规范检测随 AiVision 启动，并保持默认开启状态，可在页面手动关闭。
- 安检流程规范 API 随 AiVision 启动，但检测 worker 默认关闭；点击开启后，
  AiVision 才使用 security_vlm/configs/config.yaml 中配置的 Conda Python
  拉起耗 token 的推理子进程。
- 不再启动 guard_room、security_vlm tmux，也不再监听 5001、8000。

AiVision 必须使用名为 aivision 的 Conda 环境，不能使用 uv。
Security VLM 的按需 worker 默认仍使用 security_vlm Conda 环境；
这个环境只运行检测子进程，不提供 Web 端口。

首次启动时，如果 scripts/auth_secret 不存在，脚本会提示输入 yes 后生成。
后续会复用该文件，并把同一个 AUTH_SECRET 注入 unified_backend 和 aivision。

以下为单独启动某个服务的排障备用方式，正常运行优先使用 scripts/start.sh。

1、启动 unified_frontend：
tmux new -s unified_frontend
cd unified_frontend
npm run dev
如需临时改端口：npm run dev -- --port <前端调试端口>

2、启动 unified_backend（固定 5000）：
tmux new -s unified_backend
conda activate unified_backend
export AUTH_SECRET="<与 AiVision 保持同一串 32 位以上随机密钥>"
python -m unified_backend.run_server
如需临时改端口：python -m unified_backend.run_server --port <统一后端调试端口>

3、启动 AiVision（固定 7862，同时承载全部检测功能）：
tmux new -s aivision
conda activate aivision
cd AiVision
export AUTH_SECRET="<与统一后端保持同一串 32 位以上随机密钥>"
# 可选：物流通道单路检测结果超过多少秒按“未知”处理，默认 5 秒。
export LOGISTICS_STATUS_STALE_SECONDS=5
python main.py --host 127.0.0.1 --port 7862
如需临时改端口：python main.py --port <AiVision 调试端口>

首次部署环境：
conda create -n aivision python=3.11 -y
conda run -n aivision python -m pip install -r AiVision/requirements.txt

Security VLM 按需 worker 环境不存在时：
conda create -n security_vlm python=3.11 -y
conda run -n security_vlm python -m pip install -r security_vlm/requirements.txt

物流通道单人检测上线说明：
- 通用电气、电子电工、电气部件、贵金属回收四个模块都在各自前端配置页按“物流通道”管理。
- 每个通道最多绑定 9 路摄像头，画面自动使用单画面、左右、2×2 或 3×3 布局；ROI 按摄像头独立保存。
- 检测时间段、无人/多人持续时间和报警配置按通道独立设置。
- 任一路出现 2 人及以上进入多人报警；所有在线且结果新鲜的摄像头都为 0 才进入无人报警。
  离线、过期或无结果按未知处理，不能当作 0 人。
- 前端经统一后端访问 /api/v2/logistics-channels/{feature}，统一后端转到 AiVision 同名接口。

首次用新版启动 AiVision 前先备份数据库。启动流程会自动创建物流通道相关新表，
并迁移四个旧物流 feature 中尚未归属通道的已启用摄像头。重复启动不会重复创建。

如何管理用户

  使用管理员账号登录前端，在左侧“系统管理”中进入“用户管理”。

  管理员可以：
  - 添加管理员或指定事业部的普通用户；
  - 修改用户姓名、角色和事业部；
  - 启用或禁用用户；
  - 重置用户密码；
  - 永久删除用户。

  第一次启动新版统一后端时，系统会自动把现有
  auth/auth_users.json 中的全部账号迁移到：

  /srv/Fuda_CVPreject/runtime/auth/auth_users.db

  迁移只执行一次。完成后登录和用户管理只读写数据库，
  不再通过修改 auth/auth_users.json 添加用户。

  备份用户数据库：

  cp runtime/auth/auth_users.db \
    "runtime/auth/auth_users.db.backup-$(date +%Y%m%d-%H%M%S)"

  数据库文件位于 runtime/ 目录，不会提交到 Git。
