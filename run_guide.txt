福达视觉平台运行与部署手册
==========================

公网网址：https://aicv.fudar.com/

一、当前服务拓扑
----------------

生产环境统一由 scripts/start.sh 管理两个 tmux 服务：

- unified_frontend：Vite 前端，监听 0.0.0.0:3000；
- aivision：唯一 API 服务与全部视觉检测业务，默认监听 0.0.0.0:7862，地址和端口由 API_HOST、API_PORT 配置。

公网网关只需把 https://aicv.fudar.com/ 转发到项目服务器 TCP 3000。
7862 仅供本机前端代理调用，不应直接开放到公网。

保安行为和安检流程检测均为 AiVision 原生功能，摄像头由平台统一管理，检测配置和历史写入同一 MySQL。
安检使用 config/model_paths.yaml 中的 yolo_human 人体模型；内部福达AI接口与推理参数在管理页面保存到数据库。

二、首次部署
------------

以下示例假设项目位于 /srv/Fuda_CVPreject；实际路径不同时请对应替换。

1. 安装系统依赖

apt update
apt install -y tmux iproute2 curl wget vim

2. 准备 Python 3.11 环境

Python 依赖按各服务目录中的 requirements.txt 安装。

AiVision 必须使用名为 aivision 的 Conda 环境：

conda create -n aivision python=3.11 -y
conda run -n aivision python -m pip install \
  -r /srv/Fuda_CVPreject/AiVision/requirements.txt

3. 准备 Node.js 20 和前端依赖

node -v
cd /srv/Fuda_CVPreject/unified_frontend
npm ci

统一启动脚本会运行 Vite，不依赖仓库内 dist 目录，也不需要项目专用 Nginx 配置。

4. 准备运行配置和数据

以下真实配置、密钥和运行数据不提交到 Git，新服务器需要从当前生产环境安全复制：

- AiVision/.env：MySQL 等 AiVision 配置；
- AiVision/config/model_paths.yaml：含 Guard 模型在内的平台共享模型路径；
- scripts/auth_secret：如需保持现有登录态；
- unified_frontend/.env.local：仅在覆盖默认前端配置时需要。

用户、访问审计、报警处置和检测业务均写入同一 MySQL。连接同一数据库的其他服务器无需重复迁移；只需准备本机模型路径和数据库连接。
前端 API 代理目标使用 VITE_AIVISION_TARGET，默认 http://127.0.0.1:7862。

示例：

scp <当前生产机器>:/srv/Fuda_CVPreject/AiVision/.env \
  /srv/Fuda_CVPreject/AiVision/.env

scp <当前生产机器>:/srv/Fuda_CVPreject/scripts/auth_secret \
  /srv/Fuda_CVPreject/scripts/auth_secret
chmod 600 /srv/Fuda_CVPreject/scripts/auth_secret

如默认路径或环境名不同：

cp scripts/start.env.example scripts/cold_start.env
vi scripts/cold_start.env

三、日常启停与检查
------------------

以下命令均在项目根目录执行：

bash scripts/start.sh          # 启动；已有同名会话时安全跳过
bash scripts/start.sh --force  # 等待已有请求及后端退出后重启当前两个服务
bash scripts/status.sh         # 查询 tmux、端口和 health
bash scripts/stop.sh           # 确认后停止当前两个服务
bash scripts/stop.sh -y        # 无交互停止当前两个服务

正常停止时会先拒绝 AGV 新请求，保持模型和采集运行，等待已接收请求完成检测和
同步返回或后台回调后再退出。AiVision/.env 中 SHUTDOWN_GRACE_SECONDS 默认 75 秒；
原有单次检测和回调超时仍然有效，失败不能作为无人放行结果。

scripts/cold_start.env 中 FUDA_STOP_TIMEOUT_SECONDS 默认 180 秒，用于等待后端进程
完成请求及资源清理，应大于 SHUTDOWN_GRACE_SECONDS 并留出清理时间。超时会保留
tmux 会话并返回失败，不强杀或继续启动另一个后端；查看 aivision 日志后再处理。

更新代码时先执行 bash scripts/stop.sh -y，确认成功后更新代码，再执行
bash scripts/start.sh。请使用这两个脚本或向后端主进程发送 SIGTERM 正常停止。
暂停接收及启动期间的新请求可能收到 HTTP 503 或连接失败，需要 AGV 调用方重试；
该流程保护已接收请求，不在服务停机期间缓存新请求。

启动后应存在：

tmux has-session -t aivision
tmux has-session -t unified_frontend

查看日志：

tmux attach -t aivision
tmux attach -t unified_frontend

在 tmux 中按 Ctrl+B，松开后按 D，可退出窗口但保持程序后台运行。

健康检查：

curl -i http://127.0.0.1:7862/api/runtime/health
curl -i http://127.0.0.1:3000/

AiVision 模型加载期间可能短暂显示 DEGRADED；如果持续不恢复，进入对应 tmux 查看日志。

四、AUTH_SECRET
---------------

AiVision 使用 AUTH_SECRET 签发登录令牌。首次执行 start.sh 时，脚本会在
scripts/auth_secret 不存在的情况下提示确认并生成 32 字节随机密钥，文件权限为 600；后续
启动会复用该文件。统一前端不注入该密钥。

查看注入状态（命令会显示密钥，仅在可信终端执行）：

tmux show-environment -t aivision AUTH_SECRET

替换 scripts/auth_secret 会使现有登录令牌失效。跨服务器迁移时应连同用户数据库一起安全
复制原密钥，除非明确希望所有用户重新登录。

五、用户管理与备份
------------------

管理员登录前端后，在“系统管理 → 用户管理”中添加、修改、启停、重置密码或删除用户。
用户管理写入 auth_users，访问审计写入 auth_access_viewers；报警处置写入 ai_alarm_disposition。
使用数据库管理工具备份共享 MySQL，备份应包含账号密码哈希、权限、登录版本及业务历史。
不要将数据库备份或密钥加入版本库。

六、单服务排障启动
------------------

正常运行优先使用 scripts/start.sh；以下命令只用于排障。

前端：

cd unified_frontend
npm run dev

AiVision（在项目根目录）：

conda activate aivision
export AUTH_SECRET="<scripts/auth_secret 中现有的密钥>"
python -m AiVision.main

七、物流通道说明
----------------

- 通用电气、电子电工、电气部件、伟达公司四个模块在各自配置页管理物流通道；
- 每个通道最多绑定 9 路摄像头，ROI 按摄像头独立保存；
- 检测时段、无人/多人持续时间和报警配置按通道独立设置；
- 任一路出现 2 人及以上进入多人报警；所有在线且结果新鲜的摄像头都为 0 才进入无人报警；
- 离线、过期或无结果按未知处理，不能当作 0 人。

上线前应备份 AiVision 数据库。前端直接访问 AiVision 的 /api/logistics-channels/{feature}。

八、海康人脸库自动更新
----------------------

人脸库由独立 systemd 任务管理，依次同步海康 one、two 人员资料并增量生成人脸特征，写入共享 MySQL。
安装此任务、手动触发更新及查询状态均不需要重启前端、后端或现有算法进程。
运行中的识别 Worker 在处理识别请求时按约 60 秒周期刷新索引，自动读取有效的新特征。

以下命令以 root 账号、项目位于 /srv/Fuda_CVPreject、Python 位于
/root/miniconda3/envs/aivision/bin/python 为例；实际路径不同时请对应替换。
部署前需成功更新项目代码，并确认存在 AiVision/face_library.py。
如果 git pull 被本地修改或未跟踪文件阻止，应先保留并处理这些改动，再继续安装任务。

1. 校验入口并安装或更新定时任务

cd /srv/Fuda_CVPreject
/root/miniconda3/envs/aivision/bin/python -m AiVision.face_library --check
/root/miniconda3/envs/aivision/bin/python -m AiVision.face_library --install-systemd

--check 仅校验业务入口可导入，不访问海康、数据库或加载模型。
安装命令需要 root、systemctl 和 systemd-analyze，会按当前项目目录及解释器生成配置，校验后安装到
/etc/systemd/system/，备份被替换的 unit、重载配置并检查实际生效入口，然后启用 timer 并安排一次立即更新。
安装命令成功只表示已安排执行，更新是否完成需通过状态或日志确认。
项目目录或 Python 环境发生变化时，使用目标解释器重新执行安装命令。

2. 查询自动更新状态

/root/miniconda3/envs/aivision/bin/python -m AiVision.face_library --status

查询同时核对定时器启用状态、实际执行入口、工作目录及最近执行结果。
执行中会明确显示正在更新；没有完成记录或任一阶段失败时，不会报告更新成功。
不能仅凭 timer 为 active 判断同步成功；service 成功执行后显示 inactive 是正常的 oneshot 行为。

3. 手动运行一次完整更新

systemctl start hikvision-face-library-sync.service

通过同一个 service 触发可避免与定时任务并发执行；命令会等待本次任务完成。
单次任务结束后间隔 10 分钟再次自动执行；开机约 2 分钟后首次触发，单次最长运行 30 分钟。
来源或人员失败会记录到日志并使任务返回非零，已成功提交的数据保留，未完成项在后续任务中重试。

4. 查询执行日志与调度时间

journalctl -u hikvision-face-library-sync.service -n 100 --no-pager
systemctl list-timers --all --no-pager -l

日志中分别包含人员同步和特征生成阶段，以及 one、two 的处理统计。
人员资料的 last_synced_at 只在资料实际变化时更新，不能作为任务是否持续执行的判断依据。

九、警戒围栏摄像头白名单
------------------------

在“警戒围栏 → 配置管理 → 围栏白名单”中选择摄像头，再设置人员允许状态。
每台摄像头独立管理名单，同事业部也可设置不同权限；未添加人员默认不允许通行。
管理员切换开关后即时保存并回读，普通账号只读；围栏与人脸身份识别分别维护授权。
禁入时段内所有进入 ROI 的人员仍形成异常时间报警，包括白名单人员。

已有围栏数据库部署此功能时，需要停止后端和相关写入、迁移结构后再启动后端。
前端按常规部署方式更新并刷新页面。完成部署后，日常修改白名单无需重启，
检测时约每 2 秒刷新当前摄像头授权；资料和特征自动同步不会自动允许新人员通行。

1. 只读检查（可在停止服务前执行）

cd /srv/Fuda_CVPreject
/root/miniconda3/envs/aivision/bin/python -m AiVision.migrations.security_fence_camera_authorization_20261105 --check

命令从 AiVision/.env 读取数据库配置，不启动算法、不修改数据库。
结果中的 authorization_scope 表示当前授权范围（department、camera 或 missing），
needs_migration 表示是否需要转换为摄像头授权，needs_authorization_table 表示授权表是否尚未创建，
camera_authorizations 显示各摄像头将保留的授权数量。

2. 备份数据库，停止后端及所有围栏配置、授权写入后应用

/root/miniconda3/envs/aivision/bin/python -m AiVision.migrations.security_fence_camera_authorization_20261105 --apply --offline

迁移将已有事业部授权复制到该事业部已经配置围栏的每台摄像头，保留授权时间。
停用但仍有围栏配置的设备也保留名单；未配置围栏的设备不继承权限。
只有完整保存并核对授权后才切换正式表，原表保存在 ai_security_fence_authorization_department_20261105。
迁移不修改其他摄像头参数或人脸识别授权，不会为未来加入的摄像头自动授权。
出现无效人员引用或无法确定事业部时会停止并保留原名单，应先修正数据再重试。
--offline 是操作者对停写状态的明确声明，命令不会自动停止服务。
迁移可重复执行，完成后不会恢复后来被管理员取消的授权。

3. 再次检查并启动后端

/root/miniconda3/envs/aivision/bin/python -m AiVision.migrations.security_fence_camera_authorization_20261105 --check

已有围栏数据库完成迁移后，needs_migration 和 needs_authorization_table 均应为 false。
确认检查通过，再按本指南的常规方式启动后端，检查各摄像头名单及围栏实时状态。
空库由后端正常启动创建正式结构，无需转换历史名单。
