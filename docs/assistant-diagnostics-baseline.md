## 方法与统计口径

每例重复 3 次；temperature=0.0，业务生成上限 2048，分类上限 256 tokens，单次超时 45.0 秒。
模型层直接调用 Qwen，不经过 Agent；Agent 模拟层使用固定模型输出和模拟业务工具；业务层直接调用真实保存服务；端到端层运行真实 submit、runtime、工具、保存及审计。
脚本端到端用于判断程序行为，真实模型端到端用于判断自然语言实际成功率，两者分开统计。故障注入单独标记，不能归因为模型自然故障。
端到端任务成功率只统计有明确且合法目标值、能够完成的请求；越界、无权限、故障、歧义、取消另计预期处理行为通过率。
JSON 有效率按结构化响应尝试计数；聊天正文不计入分母。工具执行成功率按实际调用计数，预期拒绝和故障注入也会降低该值，不能单独据此判断业务服务质量。
平均模型调用次数包括分类、纠正和业务请求；模型替身及故障注入不等于实际网络调用，结果中另有 real_model_calls。耗时为本次环境实测，不代表生产吞吐。
本工具同步投递任务，保留 submit、幂等和取消流程；不验证线程池压力、MySQL 行锁、GPU、摄像头连通或运行层热更新效果。

额外探针主动提交合法但偏离用户意图的指令，检验后端约束能力；探针失败不代表真实模型必然产生同类指令。探针仍通过才说明相应约束有效。
失败记录只保留场景编号、错误类型、布尔指标及工具名称。完整请求、响应和认证头均不写入报告。

- 模型额外修改未请求字段：请求仅包含人体置信度，但实际保存包含其他字段；当前工具校验合法字段及版本，未将 patch 限制在用户请求字段内。 证据：`{"requested_value_fields": ["threshold"], "changed_value_fields": ["cap_interval", "threshold"], "saved_action_count": 1, "goal_verified": false, "reported_status": "completed"}`

- 批量任务只完成一个目标：请求覆盖两个目标，实际仅完成其中一个；完成集合按工具类别记账，没有核对完整目标清单。 证据：`{"requested_value_fields": ["threshold"], "changed_value_fields": ["threshold"], "saved_action_count": 1, "goal_verified": false, "reported_status": "completed", "expected_targets": 2, "verified_targets": 1}`

- 工具纠正成功后的最终状态：检索错误已纠正，配置和审计已保存，但本轮仍报失败；工具错误一直保留在 outcome.errors 中。 证据：`{"requested_value_fields": ["threshold"], "changed_value_fields": ["threshold"], "saved_action_count": 1, "goal_verified": true, "reported_status": "failed"}`

## 证据不足

缺少或不可达的模型层会标记 blocked，不以脚本模型结果代替。即使全部虚构样例通过，也不能证明所有自然语言表达和生产部署均可靠。
Qwen 的 API model 标识不能证明实际权重、量化、chat template 或启动参数；本诊断不修改或验证模型权重。
SQLite 用于验证事务结果、字段校验和版本逻辑，不覆盖 MySQL 的锁竞争、死锁重试及生产数据规模。
多轮测试在同一 session 内持续 10～13 轮，分别覆盖混合任务、历史窗口和重复完整配置查询。逐轮记录模型请求字符数；Token 数只采用服务 usage，不进行估算。
当前后端默认仅携带最近 6 轮历史，限制轮数而不限制历史总字符；工具观察单独按 60000 字符裁剪。原始目标绑定片段的可见性只是字面证据，不能证明所有语义信息均已保留或丢失。
前端 sendAssistantMessage 只提交 request_id/text，由 useAssistant 复用 sessionId；源码未发现第 4 或第 5 轮的固定上限。本工具不运行浏览器，不能排除轮询、页面挂载或会话切换故障。

## 优先级最高的三项建议

1. 将任务约束细化到明确的部门、资源、字段及目标值，并在执行前校验 patch 和目标集合，保留现有业务权限、版本及审计。
2. 保存待澄清任务的结构化状态，按目标逐项核对完成情况，分别记录已恢复与未恢复的工具错误。
3. 在实际 Qwen 服务上运行固定对话集，分离分类、提取、工具选择和保存结果指标，再根据失败归属决定调整模型服务或 Agent。

建议应结合各层实测结果排序；未运行的层不支持对模型优劣作结论。
