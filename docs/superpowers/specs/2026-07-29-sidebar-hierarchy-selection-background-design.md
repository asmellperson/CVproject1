# 导航栏层级选中底色设计

## 目标

为侧边栏事业部一级目录和检测功能建立清晰的选中层级：

- 当前检测功能所属的一级目录显示浅蓝色底色。
- 当前检测功能显示更深的蓝色底色。
- 未选中的一级目录和检测功能不显示选中底色。

## 现状

`unified_frontend/src/components/Sidebar.tsx` 已通过 `currentPage` 判断当前检测功能，并通过 `activeChildGroupId` 找到它所属的一级目录。检测功能已有深蓝渐变选中样式，一级目录目前没有选中样式。

侧边栏允许多个一级目录同时展开，因此展开状态不能作为选中状态，否则会同时出现多个带底色的一级目录。

## 状态设计

一级目录使用 `activeChildGroupId === child.id` 判断是否选中。该值由当前页面 `currentPage` 推导，不新增独立状态：

1. 用户点击检测功能后，`currentPage` 更新。
2. `activeChildGroupId` 找到包含该检测功能的一级目录。
3. 对应一级目录显示浅蓝色选中底色。
4. 当前检测功能继续显示已有的深蓝渐变选中底色。

点击一级目录只负责展开或收起，不会改变选中状态。未包含当前检测功能的一级目录即使处于展开状态，也不显示选中底色。

## 视觉设计

选中的一级目录使用浅蓝背景、淡蓝描边、蓝色文字和轻阴影，形成接近参考图的浅色父级容器效果。暗色模式使用半透明深蓝背景及深蓝描边。

当前检测功能保留已有的深蓝渐变、白色文字和阴影。未选中状态与现有悬停效果保持不变。

字号、间距、箭头旋转、菜单数据、权限过滤和展开行为均不修改。

## 修改范围

- 修改：`unified_frontend/src/components/Sidebar.tsx`
- 新增依赖：无
- 新增业务组件：无

## 验证

1. 运行修改前后样式契约检查，确认一级目录选中样式由 `activeChildGroupId` 控制，检测功能仍使用原有选中样式。
2. 执行统一前端 `npm run build`。
3. 执行统一前端 `npm run lint`。
4. 人工确认切换检测功能时，只有当前功能及其所属一级目录显示各自底色；单纯展开其他目录不会产生选中底色。

## 风险

风险较低。该方案复用现有页面状态，不改变导航行为。自动化检查可以覆盖状态条件和样式类，但最终颜色观感仍需在实际页面中人工确认。
