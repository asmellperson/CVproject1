# 安检流程规范配置页重组设计

## 目标

将安检流程规范页面当前全局展示的摄像头操作区移入“配置管理”，并把原一级“ROI 绘制”入口改造成包含“摄像头管理”和“ROI 绘制”两个子页面的配置区。只调整页面结构和展示位置，不改变摄像头、视频、检测、ROI 接口及其数据绑定。

## 页面结构

一级导航改为：

- 实时监控
- 配置管理

配置管理内部使用二级 Tab：

- 摄像头管理
- ROI 绘制

四个事业部共用 `SecurityVlmSection`，因此一次修改同时作用于通用电气、电子电工、电气部件和贵金属回收的安检流程规范页面。

## 实时监控

实时监控保留：

- 页面标题和运行状态；
- VLM 降级状态；
- 单画面/双画面切换；
- 状态刷新；
- 数据汇总；
- 安检画面；
- 历史记录。

实时监控不再展示 `SecurityCameraBar`，也不再展示添加、编辑、单路启停、单路重启、全部开启和全部关闭等配置操作。

## 摄像头管理

配置管理的“摄像头管理”子页面包含：

- 全部开启、全部关闭和刷新；
- 原 `SecurityCameraBar` 摄像头卡片；
- 摄像头选择；
- 单路开启/关闭；
- 单路重启；
- 摄像头添加和编辑入口；
- 原 `SecurityCameraDialog`。

继续使用现有 `handleAllCameras`、`handleToggleCamera`、`handleRestartCamera`、`openCameraDialog`、`saveCamera` 和 `deleteCamera`，不新增接口，不改变权限判断和忙碌状态。

## ROI 绘制

原 ROI 绘制卡片整体迁入配置管理的“ROI 绘制”子页面，保留：

- 摄像头下拉选择；
- 新增、删除、保存 ROI；
- 原图视频地址；
- 点选、拖拽、顶点调整和坐标换算；
- ROI 热加载消息和权限限制。

`activeVideoUrl` 在配置管理的 ROI 子页面启用时继续请求 `original` 模式，实时监控继续请求 `rule` 模式。

## 状态与数据流

一级状态使用 `dashboard | config`，配置管理二级状态使用 `camera | roi`。切换页面不重建摄像头和 ROI 业务状态，仍复用同一个 `selectedCameraId`，保证从摄像头管理选择摄像头后进入 ROI 绘制时保持选择。

摄像头弹窗保持挂载在 `SecurityVlmSection` 内，避免迁移后丢失编辑、删除和凭证读取行为。

## 不在范围内

- 不修改后端接口；
- 不调整检测算法、视频播放地址或轮询周期；
- 不重新设计摄像头卡片或 ROI 绘制器；
- 不改变四个事业部的路由和权限。
