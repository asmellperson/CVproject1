# 物流通道多摄像头联合单人检测设计

## 目标

将通用电气、电子电工、电气部件、贵金属回收四个物流通道单人检测模块，从“按单台摄像头配置、显示和报警”升级为“按物流通道管理多台摄像头、拼接显示并联合判定”。

管理员可以新增具名物流通道，为每个通道绑定最多 9 路摄像头，并逐路配置 ROI。检测继续逐路执行，最终由物流通道统一决定正常、无人异常、多人异常或未知状态。

## 范围

本次设计覆盖：

- AiVision 物流通道、通道成员和通道级配置的数据模型；
- 四个物流单人检测消费者的共用检测与通道聚合逻辑；
- 物流通道管理、摄像头绑定、独立 ROI、通道状态及拼接帧接口；
- 四个物流模块共用的前端监控与配置组件；
- 现有单摄像头配置向物流通道的幂等迁移；
- 告警记录、截图、企微及其他已有通知链路的通道化适配；
- 单元、接口、前端契约及必要集成测试。

本次不改造保安行为检测服务，不把物流检测运行时迁入 `guard_room`，也不改变人员检测模型本身。

## 总体方案

物流通道能力实现在 `AiVision` 内，复用保安室功能的产品交互方式，但不复用其独立数据库表或运行时。现有摄像头资源、推理调度、配置事件和告警基础设施继续作为底层能力。

四个模块使用一套共享实现，通过受控的物流检测 `feature_name` 区分。后端只接受白名单中的四个功能标识，数据查询同时遵守现有部门和角色权限，防止跨模块访问。

数据流为：

1. 摄像头读取最新帧；
2. 对该摄像头的 ROI 执行人体检测；
3. 生成逐路人数和标注帧快照；
4. 通道聚合器读取各成员的最新有效快照；
5. 生成通道状态并执行持续时间判定；
6. 异常成立时保存通道告警和拼接证据；
7. 状态接口和拼接帧接口向前端提供统一结果。

## 数据模型

### 物流通道

新增物流通道实体，至少包含：

- 主键；
- 通道名称；
- 物流检测 `feature_name`；
- 启用状态；
- 排序值；
- 每日检测开始和结束时间；
- 无人持续时间；
- 多人持续时间；
- 告警开关及现有告警目标配置；
- 创建和更新时间。

同一 `feature_name` 下通道名称唯一。默认每日检测时间为 `08:00–20:00`，时间和持续阈值必须通过统一配置模型读取，不在消费者业务逻辑中硬编码。

### 通道摄像头成员

新增物流通道成员实体，至少包含通道 ID、现有 AiVision 摄像头 ID、启用状态、排序值及创建和更新时间。

约束如下：

- 每个通道最多绑定 9 路启用摄像头；
- 同一摄像头在同一个物流检测 `feature_name` 中最多属于一个通道；
- 绑定只引用现有摄像头，不复制 RTSP 地址或摄像头记录；
- 摄像头可以继续参与其他非物流检测功能；
- 从通道移除摄像头只解除绑定并停用对应物流检测，不删除全局摄像头。

### 配置职责

摄像头级配置保留：

- ROI；
- 推理置信度和 IoU 阈值；
- 最小框面积、宽高比等检测过滤参数；
- 与单路采集和推理直接相关的配置。

通道级配置负责：

- 通道启用状态；
- 每日检测开始和结束时间；
- 无人和多人持续时间；
- 告警开关和接收设置。

配置接口必须返回明确的响应模型，不返回随意拼接的未声明字典。

## 检测与联合判定

### 单路人数

每路摄像头继续独立推理。若一台摄像头配置多个 ROI，检测框先映射回完整画面坐标，再按统一的重叠判定去重，最后得到该摄像头 ROI 范围内的唯一人数。这样可以避免同一个人同时落入重叠 ROI 时被重复计数。

每路快照至少包含：

- 摄像头 ID 和名称；
- 人数，无法判断时为 `null`；
- 快照状态：`normal`、`empty`、`multiple` 或 `unknown`；
- 结果更新时间；
- 标注画面更新时间；
- 在线状态及未知原因。

结果超过统一运行配置 `LOGISTICS_STATUS_STALE_SECONDS` 的新鲜度阈值，或摄像头离线、没有检测结果时，按 `unknown` 处理，不能按 0 人处理。该阈值默认 5 秒，可通过环境配置调整。

### 通道判定表

通道只聚合已启用成员，优先级固定如下：

| 条件 | 通道状态 | 是否进入报警计时 |
|---|---|---|
| 任意已获得有效结果的摄像头人数大于等于 2 | `multiple` | 是，按多人持续时间 |
| 所有启用摄像头均有新鲜结果且人数均为 0 | `empty` | 是，按无人持续时间 |
| 不存在多人摄像头，且至少一台摄像头人数为 1 | `normal` | 否 |
| 不存在多人摄像头，存在未知摄像头，其他摄像头均为 0 | `unknown` | 否 |
| 通道没有启用摄像头 | `unconfigured` | 否 |
| 通道停用或不在检测时间段 | `inactive` | 否 |

因此，两台或多台摄像头各出现 1 人仍为正常；任意单台摄像头出现 2 人或更多即进入多人异常计时；只有全部启用摄像头都明确为 0 人时才能进入无人异常计时。

### 时间状态

无人和多人状态按通道连续计时。状态改变、恢复正常、进入未知、通道停用、离开检测时间段或成员配置发生变化时，对不再成立的计时状态清零。

持续时间达到阈值后生成通道告警。同一异常持续期间沿用现有告警去重和冷却策略，避免按帧重复推送；恢复后再次发生异常可以创建新告警。

运行时使用带锁状态或不可变快照交换，确保多路消费者并发更新时不会读取到半更新数据。成员、ROI 或通道配置更新后，通过现有配置事件机制刷新相关缓存，无需重启整个 AiVision。

## 告警与证据

通道告警至少记录：

- 物流检测 `feature_name`；
- 通道 ID 和告警发生时的通道名称；
- 异常类型 `empty` 或 `multiple`；
- 各成员摄像头的人数、状态和结果时间；
- 多人异常对应的摄像头 ID 和名称；
- 告警开始时间、达到阈值时间及已有告警公共字段。

告警证据使用当时最新的通道拼接画面。每个格子显示摄像头名称、人数、在线状态和 ROI，多人异常时突出对应摄像头。历史告警保留通道名称快照；之后重命名或删除通道不改变历史记录。

数据库、企业微信、警号及已有通知能力继续通过当前告警基础设施执行，但触发源从单摄像头决定改为通道聚合器决定。

## 拼接画面

布局根据启用成员数量自动选择：

- 1 路：单画面；
- 2 路：左右两格；
- 3–4 路：2 × 2；
- 5–9 路：3 × 3。

成员排序决定画面位置。每格保持原始宽高比，使用补边适配统一格子尺寸，不拉伸视频。暂时没有画面的成员使用带摄像头名称和“离线”或“等待画面”原因的占位格，保证画面顺序和整体尺寸稳定。

拼接发生在各路推理和标注之后，只负责展示和告警证据，不在拼接后的大图上重新执行人体检测。

## API 设计

接口按资源职责拆分：

- 物流通道列表、新增、详情、更新和删除；
- 通道摄像头列表、新增或绑定、移动、排序、启停和移除；
- 单路摄像头物流检测配置及 ROI 读写；
- 通道级时间、持续阈值和告警配置读写；
- 通道实时状态；
- 通道最新拼接 JPEG 帧；
- 通道历史告警及统计所需查询。

通道及成员写操作仅允许 admin。viewer 可以读取其有权限模块的通道、配置、状态、画面和告警。

“新建摄像头并绑定通道”必须以事务方式完成摄像头创建、对应物流功能配置创建或启用、通道绑定；任何步骤失败都回滚，不能留下半配置资源。删除通道只删除通道和绑定关系，不删除全局摄像头。

## 前端设计

四个物流模块改用共享页面容器、共享监控视图和共享配置视图，页面标题和 `feature_name` 由模块声明传入，不复制四套业务逻辑。

### 监控页面

- 监控对象选择器展示物流通道；
- 状态卡展示通道状态、在线和离线摄像头数量、各路人数摘要及今日通道告警数；
- 主区域展示拼接画面；
- 摄像头列表展示名称、当前人数、在线状态和更新时间；
- 通道降级时明确列出离线或结果过期的摄像头；
- 保留手动刷新能力，不改变现有鉴权和未授权跳转机制。

### 配置页面

- 新增、选择、重命名、启停和删除物流通道；
- 输入摄像头名称和 RTSP 地址，在当前通道内新建摄像头；
- 选择已有摄像头并绑定或移动到当前通道；
- 调整成员顺序；
- 选择单路摄像头绘制并保存独立 ROI；
- 编辑每日检测开始和结束时间、无人持续时间、多人持续时间及告警配置；
- viewer 显示只读状态，所有修改控件禁用并给出权限说明。

## 迁移与兼容

schema 升级和数据迁移必须幂等。对于四个物流模块中当前已启用的每个摄像头：

1. 创建一个与摄像头同名、属于对应 `feature_name` 的物流通道；若同一功能内名称冲突，则稳定追加摄像头 ID；
2. 将摄像头绑定为该通道的第一个成员；
3. 保留摄像头现有 ROI 和推理过滤参数；
4. 将现有无人、多人持续时间和告警配置复制到通道配置；
5. 保留原启用状态；
6. 已存在匹配迁移关系时跳过，不重复创建。

迁移不自动猜测哪些旧摄像头属于同一物理通道。管理员后续通过移动成员完成实际分组，避免上线时改变既有报警语义。迁移失败必须记录具体模块、摄像头和原因，不能静默忽略。

兼容期内，旧摄像头级持续时间和告警字段可以保留但不再参与物流通道裁决；全部读写方迁移完成并经过独立清理评审前不删除旧字段。

## 异常处理

- 空通道显示 `unconfigured`，不触发无人告警；
- 离线或过期结果按未知处理，并在页面展示原因；
- 任一已知摄像头多人时，即使其他摄像头未知，也可以触发多人告警；
- 存在未知摄像头时不能认定“所有摄像头无人”；
- 拼接失败不阻断检测裁决，告警记录仍保存结构化状态，并记录证据生成失败原因；
- 配置校验错误返回明确字段和原因；
- 摄像头达到 9 路、名称重复、重复绑定、跨权限模块访问等情况返回明确的业务错误；
- 后端记录配置加载、通道状态切换、离线降级、告警触发和失败原因，不使用静默异常处理。

- 完整通道判定表；
- 两路各 1 人为正常，任一路 2 人或更多为多人异常；
- 全部为 0 才能进入无人异常；
- 离线、过期、空通道、停用通道和非检测时间；
- 无人和多人持续时间、状态切换和恢复清零；
- 多 ROI 坐标映射和人体框去重；
- 并发快照更新的一致性；
- 1、2、4、9 路拼接尺寸、顺序、比例保持和离线占位。

## 风险与控制

- 多路结果异步到达可能造成瞬时误判：使用新鲜度检查、原子快照和通道级连续计时控制。
- 重叠 ROI 可能重复计数：映射到完整画面后统一去重。
- 拼接画面增加 CPU 和内存开销：只对前端请求和告警证据按需生成，并复用最新标注帧，不重复推理。
- 四个现有消费者存在重复实现：抽取物流单人检测共享基类或共享服务，但只重构与本功能直接相关的重复逻辑。
- 旧配置与新通道配置并存可能产生来源歧义：运行时只读取通道级裁决配置，旧字段仅为兼容保留，并通过测试锁定配置优先级。
