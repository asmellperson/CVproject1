# 物流通道摄像头成员选择与新建交互设计

## 背景

物流通道单人检测的“配置管理 → 摄像头成员”存在两个交互问题：

1. “绑定已有摄像头”的下拉列表较长时，用户使用鼠标滚轮向下浏览，列表会跳回开头。
2. “新建摄像头并绑定”长期占用卡片空间，与保安行为规范检测中通过按钮打开弹窗的添加摄像头交互不一致。

本次只调整前端交互，继续复用现有物流通道摄像头创建、绑定和刷新接口，不修改后端接口或数据结构。

## 目标

- 已有摄像头下拉列表可以稳定使用鼠标滚轮浏览后续摄像头。
- 将内嵌的新建表单替换为按钮触发的弹窗。
- 弹窗保留摄像头名称、FPS、RTSP 地址三个现有字段。
- 提交成功后一次完成摄像头创建和当前通道绑定，并刷新成员及摄像头数据。
- 修改局限在物流配置交互和通用 Select 的可选能力，不改变其他页面现有行为。

## 非目标

- 不修改物流通道后端 API。
- 不把保安行为规范检测和物流检测的摄像头数据模型合并。
- 不为物流弹窗新增“测试连接”能力；当前物流接口没有对应能力。
- 不重构物流配置页中与本任务无关的通道、ROI 或规则逻辑。

## 方案选择

采用“物流专用弹窗 + 通用 Select 局部开关”方案。

不直接复用 `SecurityCameraDialog`，因为保安摄像头只有名称和 RTSP 地址，并具有独立的测试、编辑和删除接口；物流摄像头还需要 FPS，提交语义是“创建并绑定当前通道”。强行复用会把不同业务流程耦合到一个组件。

不把弹窗表单继续堆入 `LogisticsChannelConfigView.tsx`。新建独立组件可以把输入状态、校验、忙碌状态和错误展示封装起来，避免继续扩大现有配置组件。

## 组件设计

### 通用 Select

在 `SelectContent` 增加一个默认开启的可选属性，用于控制是否渲染 `SelectScrollUpButton` 和 `SelectScrollDownButton`。

- 默认值保持开启，确保项目中其他 Select 行为不变。
- “绑定已有摄像头”下拉框显式关闭这两个按钮。
- `SelectPrimitive.Viewport` 和已有最大高度样式继续负责滚轮滚动。

这样可以避开 Radix Select 2.2.6 在滚动按钮挂载时对焦点项调用 `scrollIntoView()`、把未选择状态下聚焦的第一项拉回视口的问题。

### 物流摄像头创建弹窗

新增物流专用弹窗组件，视觉和结构参考 `SecurityCameraDialog`，使用项目已有的 `Dialog`、`Input`、`Label` 和 `Button`。

弹窗包含：

- 摄像头名称：必填，提交前去除首尾空格。
- FPS：必填，必须是大于等于 1 的整数。
- RTSP 地址：必填，提交前去除首尾空格。
- 取消按钮：无提交进行时关闭弹窗。
- “新建并绑定”按钮：字段有效且未提交时可用。
- 提交中状态和弹窗内错误提示。

弹窗只负责表单交互，通过 `onSubmit` 回调把规范化后的数据交给父组件，不直接依赖物流 API。

### 物流摄像头成员页面

`LogisticsChannelConfigView` 将两种绑定方式放在同一张“绑定摄像头”卡片内。卡片下方分为“绑定已有摄像头”和“新建摄像头并绑定”两个选项；前者保留现有下拉选择与移动开关，后者以按钮打开创建弹窗。页面删除当前内嵌的三个输入框，并维护弹窗开关。

按钮在以下情况禁用：

- 当前用户不是管理员；
- 当前没有选中的物流通道；
- 当前通道已经有 9 个摄像头成员；
- 页面正在执行其他成员操作。

## 数据流

1. 用户点击“新建摄像头并绑定”。
2. 页面打开物流摄像头创建弹窗。
3. 用户填写名称、FPS 和 RTSP 地址并提交。
4. 弹窗调用父组件提供的异步 `onSubmit`。
5. 父组件调用现有 `addLogisticsChannelCamera`，沿用当前“创建并绑定”请求结构。
6. 请求成功后：
   - 关闭并卸载弹窗，使表单状态自然重置；
   - 刷新物流通道列表、当前通道详情和成员归属数据；
   - 触发已有 `aivision:cameras-changed` 事件，使页面重新读取全局摄像头列表；
   - 在配置页显示“摄像头已新建并绑定”的成功消息。
7. 请求失败时弹窗保持打开，在弹窗内展示可读错误，用户可以修改后重试。

## 错误与并发处理

- 提交期间禁用输入、取消和提交操作，避免重复请求或中途关闭。
- API 错误不静默吞掉，弹窗显示错误原因。
- 只有请求成功才关闭弹窗。
- 页面原有 `busy` 防重逻辑继续保护其他成员操作；弹窗内部使用独立提交状态，避免把整个配置页锁死。
- 弹窗打开期间如果当前通道被切换或删除，提交前由父组件重新校验当前通道；没有有效通道时拒绝提交并给出错误。

## 测试与验证

最小自动验证覆盖：

- 通用 `SelectContent` 的滚动按钮属性默认保持现有行为。
- 物流已有摄像头下拉框关闭滚动按钮。
- 摄像头成员页显示弹窗触发按钮，不再内嵌新建表单。
- 弹窗包含名称、FPS、RTSP 地址，并按必填及整数规则控制提交。
- 成功提交调用现有创建绑定流程并触发成员、通道和摄像头刷新。
- 失败提交保持弹窗打开并展示错误。

实现后运行前端相关 Node 测试、TypeScript 构建或项目现有最小前端验证命令，并人工检查长摄像头列表的鼠标滚轮行为。

## 风险

- 关闭 Radix 上下滚动按钮后，列表仍可使用滚轮、触控板和键盘导航，但不再提供鼠标悬停自动滚动区域；该变化只应用于物流已有摄像头下拉框。
- 摄像头创建成功后的多路刷新可能产生重复请求，但全部使用项目现有失效与刷新机制，不改变最终状态。
- 如果后端返回的 FPS 校验规则比当前前端更严格，仍以后端错误为准并在弹窗中展示。
