# ROI 编辑器根因修复设计

## 背景

物流通道逐路 ROI 编辑页同时显示红色和蓝色 ROI，并且编辑中的点位会恢复为服务端已保存值。红线来自后端功能标注帧，蓝线来自前端 SVG 编辑层；物流通道详情的定时轮询还会反复触发逐路配置加载，覆盖尚未保存的前端草稿。

## 目标

- ROI 编辑器只以原始摄像头帧作为绘制底图，避免服务端标注与前端编辑层重复显示。
- 物流通道逐路 ROI 只在功能、通道或摄像头身份发生变化时加载配置。
- 保持与人体逗留检测相同的现有交互：点击画点、拖动顶点、撤销、清空和保存。
- 不增加按钮，不引入新的编辑模式，不修改后端检测画面的标注逻辑。

## 设计

### 原始帧预览

共享 `AiVisionRoiEditor` 的预览请求不再携带功能名称。没有 `feature` 参数时，摄像头帧接口返回原始帧；已保存 ROI 仅由前端 SVG 编辑层绘制一次。监控页面仍继续请求功能标注帧，不受本次修改影响。

`feature` 不再属于 ROI 编辑器的有效输入。调用端移除该属性，避免接口继续暗示 ROI 编辑器需要标注帧。

### 配置加载身份

物流通道逐路配置加载以三个稳定值作为身份：功能名称、通道 ID、摄像头 ID。通道详情轮询即使返回新的对象，只要这三个值不变，就不重新读取逐路配置，也不覆盖 `roiJson` 草稿。

切换功能、通道或摄像头时仍会读取对应的最新配置；保存逻辑和服务端数据结构保持不变。

## 验证

- 回归测试确认 ROI 编辑器生成的预览 URL 不包含 `feature`。
- 回归测试确认物流通道逐路配置加载依赖稳定 ID，而不是整个轮询详情对象。
- 运行相关前端测试、定向 ESLint 和生产构建。

## 风险与边界

- 本次修改会让所有复用 `AiVisionRoiEditor` 的配置页使用原始帧，这是 ROI 编辑场景的一致性修复。
- 功能监控画面仍使用标注帧，不改变检测结果展示。
- 不改变已有 ROI 的坐标格式、保存接口或后端推理行为。
