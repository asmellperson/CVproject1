# 前端闲置后页面加载卡死治理设计

## 背景与现场证据

浏览器在某个页面停留十几分钟后，首次进入另一个尚未加载的页面时会长期显示“正在加载页面...”；重新打开 `localhost:3000` 后暂时恢复。

现场 Network 记录已经确认：

- `GET /api/platform/status` 由侧边栏每 10 秒发起，但单次请求曾耗时 1.6～2.4 分钟并最终返回空响应的 `400 Bad Request`。
- 多条状态请求同时处于等待状态，耗时呈现明显的重叠和排队。
- 实时帧请求能够按现有 5 秒保护主动取消，说明帧请求本身已有超时，但同一时期其他 API 请求仍普遍变慢。
- 新页面对应的 Vite TSX 动态模块请求曾等待约 20 秒后返回 `400`，直接触发应用级 `Suspense` 长时间显示“正在加载页面...”。
- 当前长期运行入口使用 Vite 开发服务器的 `3000` 端口；页面模块和 API 代理共享同一来源。

代码中的对应原因是：

- `Sidebar` 和 `HomeSection` 都会周期性调用 `getPlatformStatus`。
- 轮询使用固定 `setInterval`，不等待上一次请求完成，也不取消卸载后的在途请求。
- 普通 `fetch` 没有统一的超时保护。
- 后端 `platform_status` 使用同步、串行的上游请求，并对每个 Guard Room site 再请求一次状态；单次聚合耗时可能超过前端轮询周期。
- 页面动态导入没有时间上限和错误边界；模块请求失败后缺少可恢复界面。

## 目标

- 任一浏览器实例对同一轮询任务最多保留一个在途请求。
- `/api/platform/status` 在上游部分异常时仍能在固定总时限内返回结构化降级结果。
- 多个组件、标签页或同权限用户同时查询状态时，不重复执行相同的聚合工作。
- 页面模块加载失败或超时时，不再无限显示 loading，而是显示明确错误并允许重新加载或切换页面。
- 保持现有平台状态响应结构、认证权限、业务页面和实时帧 5 秒超时语义。
- 不增加新的第三方依赖。

## 非目标

- 不修改模型推理、摄像头采集、检测规则、告警逻辑或数据库结构。
- 不改变现有用户权限模型，也不跨权限范围共享状态缓存。
- 不通过增加 Uvicorn worker 数量掩盖同步聚合和请求重叠问题。
- 核心修复阶段不直接切换正式服务器部署方式；Vite 开发服务与 Nginx 生产部署拆成独立的后续运维任务。

## 总体方案

修复按四个可独立验证的阶段推进：

```text
浏览器轮询
  -> 串行调度 + 单次超时 + 卸载取消
  -> /api/platform/status
  -> 按权限范围 single-flight + 短缓存
  -> 有界并发探测 Guard Room / AiVision / Security VLM
  -> 固定总时限内返回正常或 degraded 状态

页面切换
  -> 有时限的动态 import
  -> 成功渲染页面
     或由页面错误边界显示可恢复错误
```

阶段一先阻断浏览器请求积压；阶段二消除后端聚合瓶颈；阶段三保证页面加载失败可恢复；阶段四再把相同轮询纪律迁移到其他页面。每一阶段单独提交和验证，不混入无关重构。

## 阶段一：前端串行状态轮询

### 轮询行为

提供一个职责单一、可复用的串行轮询机制，供 `Sidebar` 和 `HomeSection` 首先使用：

- 挂载后立即执行一次。
- 本次异步任务完成、失败或超时后，才安排下一次执行；不再使用会重叠的固定 `setInterval`。
- 每次任务创建独立 `AbortController`，默认 8 秒后中止。
- 清理 effect 时立即停止计时器并中止当前任务，解决 React 开发模式 StrictMode 首次重复挂载遗留请求的问题。
- `document.visibilityState` 为 hidden 时不启动新一轮；重新可见后立即刷新一次。
- 平台状态轮询间隔调整为 30 秒。超时或主动取消不会覆盖最后一次成功结果；真实网络或 HTTP 错误沿用现有“平台连接异常”表现。

轮询调度与 React 页面展示分离。调度核心接受可注入的定时器函数，便于使用当前项目的轻量 TypeScript 测试风格验证“无重叠、超时取消、停止后不再调度”。React hook 只负责生命周期和页面可见性。

### API 调用

`apiGet` 已接受 `RequestInit`，继续通过其中的 `signal` 传递取消，不另建第二套 HTTP 客户端。`getPlatformStatus` 增加可选 `RequestInit` 参数，并保持所有现有无参数调用兼容。

`HomeSection` 中状态、报警和摄像头的加载不再放在一个无法分别取消的 `Promise.allSettled` 轮询中：平台状态使用串行轮询；报警和摄像头保留当前独立结果语义，后续按同一机制迁移。这样状态超时不会阻止其他首页数据更新。

## 阶段二：后端平台状态聚合服务

### 模块边界

将平台状态探测和聚合从 `unified_backend/app.py` 抽到专用模块。路由只负责读取当前认证用户、构造权限范围键并调用服务，不继续承载上游探测业务。

服务在 FastAPI lifespan 中创建并关闭，内部复用一个 `httpx.AsyncClient`。项目已经依赖 `httpx`，因此不新增依赖。

### 探测流程

聚合分两波执行：

1. 并发请求 Guard Room health/status/sites、AiVision health/status/cameras 和 Security VLM health。
2. Guard Room sites 返回后，对各 site status 使用有界并发探测，默认最大并发数为 8。

每个上游请求默认最多等待 2 秒，整个聚合刷新默认最多等待 5 秒。到达总时限后取消未完成探测，并把对应服务或 site 标记为不可用；已经成功的数据继续参与汇总。上游部分异常属于平台状态内容，不转换为接口自身的空 `400`。

认证请求头和 cookie 继续按现有白名单规则转发，不记录 token、cookie 或摄像头凭据。

### Single-flight 与缓存

- 缓存键使用当前用户的权限范围，即规范化后的 `(role, department)`；不同权限范围绝不共享缓存。
- 同一缓存键在同一时刻只允许一个刷新任务，其他请求等待并共享该任务结果。
- 成功或降级结果缓存 5 秒，以合并 Sidebar、HomeSection、多标签页和同权限用户的同时请求。
- 客户端断开不得取消其他调用者共享的刷新任务。
- 过期缓存按访问时清理，不引入持久化状态。

输出继续保持现有 `ok`、`level`、`generated_at`、`summary` 和 `services` 结构。正常在线、部分异常和全部不可用的 level 判定规则保持不变。

## 阶段三：页面动态加载失败恢复

页面级 `React.lazy` 使用统一包装：

- 动态 import 默认最多等待 15 秒。
- 请求失败、返回非模块响应或超过时限时，让错误进入页面级 Error Boundary。
- Error Boundary 只包裹主内容区，Sidebar 和 Topbar 保持可操作。
- 错误界面显示“页面资源加载失败”，提供“重新加载当前应用”和“返回首页”两个操作。
- 当前页面键变化时重置边界，使用户无需整页刷新也能尝试其他已可用页面。
- 不执行自动无限刷新，避免端口或代理持续异常时形成刷新循环。

现有“正在加载页面...”仍作为正常短暂加载提示，但不会永久停留。

## 阶段四：其他轮询点治理

在前三阶段稳定后，按页面逐个迁移以下轮询：

- `AlarmsSection`：当前 5 秒轮询。
- `StatisticsSection`：当前 30 秒轮询。
- `SecurityVlmSection`：当前 2 秒轮询。
- `MonitorSection`：当前 1 秒状态轮询。
- `HomeSection` 中剩余的报警和摄像头刷新。

每次只迁移一个页面，保持原有刷新频率与显示行为，只增加串行、超时、卸载取消和页面不可见暂停。`AiVisionMonitor` 的帧读取已经采用“单次完成后再调度”和 5 秒取消，保持不变。

## 错误处理与日志

- 前端超时使用 `AbortError` 路径，不产生未处理 Promise；组件卸载导致的取消不显示错误。
- 状态轮询真实失败时保留现有 UI 语义，不弹出高频 toast。
- 后端记录单次聚合总耗时、超时的上游名称、缓存命中和降级级别；正常高频成功不使用 warning 级别。
- 日志不得包含 cookie、Authorization、RTSP 地址或用户密码。
- 聚合服务自身发生未预期错误时返回结构化的 down/degraded 快照并记录异常，不返回空响应。

## 测试设计

### 前端自动测试

- 上一次任务未完成时不会启动下一次轮询。
- 任务完成后按配置间隔安排下一次。
- 8 秒超时会触发当前 `AbortController`。
- stop/unmount 会取消当前请求并清除后续调度。
- 页面 hidden 时暂停，恢复 visible 后立即刷新。
- 动态 import 超过 15 秒时进入失败路径。
- 页面键变化能够重置错误边界。

测试沿用现有无额外框架的 TypeScript 小型测试方式；需要 React DOM 行为的边界测试优先提取纯状态转换和超时函数，生产构建负责类型与组件集成校验。

### 后端自动测试

- 多个慢探测能够同时进入，证明不再串行。
- 单个上游超时不会拖过整体 5 秒预算。
- 多个同权限并发请求只执行一次真实刷新。
- 不同 `(role, department)` 不共享缓存。
- 部分上游失败仍返回兼容的 degraded JSON。
- 缓存命中不重复访问上游，过期后会刷新。
- 应用关闭时正确关闭共享 HTTP 客户端。

使用 `httpx.MockTransport` 和可控事件构造测试，不要求真实启动 Guard Room、AiVision、Security VLM 或模型进程。

### 现场验收

在允许验证且不会与用户当前服务冲突的窗口执行：

1. 打开用户管理或检测页面并停留至少 20 分钟。
2. Network 中同一浏览器不出现多条并行的 `/api/platform/status`。
3. 正常状态响应目标小于 3 秒；上游异常时在 5～8 秒内返回降级结果或由前端中止。
4. 首次进入一个尚未加载的 lazy 页面，模块请求成功；如果故意中断前端服务，15 秒内出现可恢复错误而非无限 loading。
5. 实时帧仍保持当前刷新和 5 秒超时行为。

## 部署后续任务

核心代码修复通过后，再单独设计并实施生产前端部署：构建 `dist`，由现有 Nginx 配置提供静态资源和 API 反向代理，`npm run dev` 仅用于开发。该任务涉及服务器构建产物、Nginx 生效方式和回滚，不与核心修复混在同一次代码提交中。

## 风险与控制

- 8 秒前端时限可能把极慢但最终成功的旧聚合视为超时；后端 5 秒总预算落地后，正常请求应明显短于该时限。
- 并发探测会提高瞬时上游连接数，因此 site status 并发固定上限为 8，不按 site 数量无限展开。
- 缓存若跨权限共享会产生数据越权风险，因此缓存和 single-flight 必须按权限范围隔离。
- 页面错误边界只能改善恢复体验，不能替代轮询和后端聚合的根因修复。
- 正式验证需要运行测试、构建并进行闲置观察；在用户仍禁止运行项目时，只能完成静态实现，不能宣称问题已经验证解决。
