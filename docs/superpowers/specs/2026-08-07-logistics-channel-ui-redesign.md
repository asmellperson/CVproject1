# 物流通道页面视觉与交互重做设计

## 目标

在不改变四个物流通道检测模块、后端聚合判定和权限模型的前提下，重做共享前端页面，并修复删除通道后旧名称残留的问题。

四个模块继续复用同一组共享组件，仅通过 `feature` 和标题区分：

- 物流通道单人检测
- 电子电工物流通道单人检测
- 电气元件物流通道单人检测
- 贵金属回收物流通道单人检测

## 已确认的视觉方向

采用方案 A：

1. 实时监控页面严格复用“人体逗留检测”页面的信息层级和版式。
2. 配置管理页面严格复用“保安行为规范检测”配置页面的视觉结构和交互模式。
3. 后端拼接画面不再绘制红色、绿色或其他状态颜色的顶部横幅。

## 页面外壳

共享 `LogisticsChannelSection` 使用与保安行为规范页面一致的页面容器：

- 浅灰页面背景、圆角大容器；
- 左侧标题与说明；
- 右侧胶囊式主标签；
- 主标签名称固定为“实时监控”和“配置管理”。

当前“通道配置”文字全部改为“配置管理”。

## 实时监控页面

`LogisticsChannelMonitorView` 按 `HumanDwellMonitorView` 重组，而不是保留当前简单上下布局。

### 顶部状态卡

四张摘要卡依次显示：

1. 通道状态：正常、无人异常、多人异常、未知、未启用或未配置；
2. 摄像头状态：在线数、离线数、总成员数；
3. 各路人数：按启用成员顺序显示；
4. 今日通道告警：今日次数和最近一次时间。

### 主体布局

主体为左窄右宽两栏：

- 左栏：监控对象、判定说明、实时事件；
- 右栏：大尺寸后端拼接画面。

监控对象使用物流通道下拉框，并提供刷新按钮。判定说明明确展示：

- 任一路摄像头出现 2 人及以上时报警；
- 所有启用摄像头都明确为 0 人时报警；
- 至少一路为 1 人且没有多人时正常；
- 离线、过期和未知结果不当作 0 人。

实时事件复用当前状态事件数据，按时间线展示正常、无人和多人变化。

### 拼接画面

- 浏览器只展示后端拼接 JPEG，不做二次分格；
- 画面中不绘制红色或绿色横幅；
- 通道状态、在线状态、人数等信息放在画面外的卡片、标题栏或侧栏；
- 离线或无帧占位仍保留摄像头名称和原因，避免完全无法辨认格子归属。

## 配置管理页面

`LogisticsChannelConfigView` 采用保安行为规范 `ConfigSection` 的结构。

### 页面标题与内部标签

顶部标题为“配置管理”，说明为“物流通道和检测规则配置”。

内部标签为：

1. 通道管理；
2. 摄像头成员；
3. 逐路 ROI；
4. 通道规则。

“保安室管理”的对应名称统一替换为“通道管理”。

### 通道管理

- 顶部右侧提供“添加通道”按钮；
- 点击后打开 `Dialog`；
- 弹窗包含通道名称输入、取消和确认添加按钮；
- 添加成功后关闭弹窗、清空输入并自动选中新通道；
- 页面主体以列表展示通道名称、启停状态、启用摄像头数/总数；
- 每行提供选择/配置和删除操作；
- 删除继续要求确认。

### 其他配置

摄像头成员、逐路 ROI、通道规则沿用现有业务能力，但使用保安行为规范配置页的卡片、标签和操作栏样式。管理员可编辑，viewer 保持只读。

## 删除通道状态修复

### 根因

当前删除流程完成 API 请求后，只触发异步轮询刷新。删除完成到轮询返回期间：

- `channels` 仍含旧通道；
- `selectedChannelId` 仍指向旧 ID；
- `selectedChannelDetail`、`channelName` 和配置表单仍保留旧值。

因此页面继续显示已删除通道名称。

### 修复策略

删除成功后立即执行本地状态收敛：

1. 从本地 `channels` 移除已删除通道；
2. 清空被删除通道的详情、运行时状态、帧、告警和配置表单；
3. 按原列表顺序选择下一通道；没有下一项则选择上一项；列表为空则选择 `null`；
4. 随后触发后端重新拉取进行最终一致性校验；
5. 旧请求依靠现有 selection token/AbortController，不能把已删除通道写回页面。

选择下一项的逻辑抽为纯函数并编写边界测试。

## 后端拼接器调整

`compose_channel_frame()` 继续负责 1、2、4、9 宫格布局、letterbox 和离线占位。

`_render_camera_tile()` 不再调用彩色 `_draw_tile_overlay()`。如 `_draw_tile_overlay()` 不再被其他路径使用，则删除该函数及仅为横幅服务的状态颜色映射和测试；占位图文字绘制继续保留。

## 错误处理

- 添加通道失败时弹窗保持打开并保留名称；
- 删除失败时不修改本地列表和选择；
- 删除成功但刷新失败时，本地已删除状态保持，显示刷新错误，不恢复旧名称；
- 空列表显示“暂无物流通道”，并为管理员提供添加入口；
- viewer 不显示可执行的添加、删除和保存操作。

## 测试策略

严格执行测试先行：

1. 前端契约/纯函数测试先验证新排版关键结构、标签文案、Dialog 添加和删除后选择规则；
2. Hook 测试先复现删除后旧名称残留，再实现本地状态收敛；
3. 拼接器测试先断言画面顶部不存在状态色横幅，再移除绘制逻辑；
4. 运行全部前端 `.mjs`、生产构建、lint；
5. 运行 AiVision 全量测试，确认拼接和报警逻辑未回归；
6. 最终更新远程 `V4` 标签到验收提交。

## 不在本次范围

- 不修改物流通道聚合判定真值表；
- 不修改数据库模型、迁移和报警元数据；
- 不改变 1 至 9 路自动布局规则；
- 不重做非物流模块页面。
