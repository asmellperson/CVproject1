# 安检摄像头控制与编辑设计

## 目标

简化安检模块摄像头状态栏，消除播放/暂停图标带来的播放器语义，并允许管理员在编辑摄像头时直接看到和修改完整 RTSP 地址。

## 界面设计

摄像头卡片不再显示 RTSP 地址，只保留：

- 摄像头名称；
- 当前运行状态或“检测会话处理中”文字；
- 开启/关闭、重启、编辑三个操作图标。

摄像头运行操作统一采用电源语义：

- “全部开启”使用 `Power`；
- “全部关闭”使用 `PowerOff`；
- 单台摄像头已停止时显示 `Power`，表示点击后开启；
- 单台摄像头运行中显示 `PowerOff`，表示点击后关闭；
- 重启继续使用 `RotateCw`；
- 编辑继续使用 `Pencil`。

图标表达按钮将执行的动作，运行状态仍由状态文字和 Badge 表达。

## RTSP 数据与权限边界

普通摄像头列表、健康状态和 viewer 可访问接口继续返回脱敏 RTSP，前端状态栏不展示该字段。

Security VLM 新增：

```text
GET /api/cameras/{camera_id}/credentials
```

接口返回指定摄像头的完整名称和 RTSP 地址。统一后端只允许管理员访问对应的：

```text
GET /security-vlm/api/cameras/{camera_id}/credentials
```

viewer 请求返回 `403`。Security VLM 的 8000 端口继续只监听或开放给本机统一后端，不作为公网接口。

管理员点击编辑图标时，前端先请求 credentials 接口，成功后再打开编辑弹窗，并将完整 RTSP 回填到输入框。请求失败时不打开弹窗，并在页面显示明确错误。

## 数据流

1. 页面通过 `/security-vlm/health` 获取脱敏的摄像头状态。
2. 管理员点击编辑图标。
3. 前端请求管理员专用 credentials 接口。
4. 统一后端验证管理员身份后代理到 Security VLM。
5. 编辑弹窗使用完整摄像头数据初始化名称和 RTSP 输入框。
6. 保存仍调用现有摄像头更新接口；运行中的摄像头继续禁止编辑。

## 错误处理

- 摄像头不存在：credentials 接口返回 `404`。
- viewer 访问：统一后端返回 `403`。
- 完整详情加载失败：前端显示“摄像头编辑信息读取失败”，不使用脱敏值或空字符串打开弹窗。
- 编辑信息加载期间禁用该摄像头的重复编辑操作。

## 验证

- 后端测试完整 RTSP 只由 credentials 接口返回，普通列表仍脱敏。
- 统一后端测试管理员可访问 credentials、viewer 返回 `403`。
- 前端构建和 lint 验证类型、图标和异步编辑流程。
- 手工确认单台摄像头卡片不显示 RTSP，三个操作图标含义明确，编辑弹窗回填完整 RTSP。

## 范围外

- 不改变摄像头注册表的存储格式。
- 不改变 RTSP 拉流、推理、ROI 或会话逻辑。
- 不在普通状态接口中向 viewer 暴露完整 RTSP。
