# 人员逗留检测监控页面重构设计

## 目标

将人员逗留检测实时监控页重构为与保安行为规范检测、物流通道单人检测一致的仪表盘布局。保留现有摄像头、配置、报警和 JPEG 帧接口，不改变检测、跟踪、告警入库、配置保存及视频轮询逻辑；复用现有通用功能状态接口，为 `detect_human` 补充其已有运行时数据。

## 页面布局

页面使用 `#F3F5FA` 背景、`#132C72` 主色、白色 `rounded-2xl` 卡片和 lucide-react 图标。

顶部为标题“人员逗留监控与配置入口”、副标题“区域逗留超时监控面板”，右侧为“实时监控 / 配置管理”圆角分段控件。

实时监控内容依次为：

1. 四张统计卡：摄像头状态、区域当前人数、逗留阈值、今日逗留告警次数；
2. 三列主体布局，左列占一列，视频卡占右侧两列；
3. 左列顺序固定为监控对象、判定说明、实时事件。

配置管理现有的摄像头管理、参数配置、ROI 绘制、模型配置和报警推送完整保留。

## 状态数据

继续使用现有路径：

`GET /api/aivision/cameras/{camera}/features/detect_human/status`

`DwellDetectionConsumer` 从现有 tracker 读取展示快照，不启动额外推理：

- `count`：所有 ROI 中 `lost == 0` 的当前可见 track 数；
- `duration_seconds`：当前可见 track 的最长逗留秒数，无人时为 0；
- `threshold_seconds`：当前配置的 `MAX_TIME`；
- `alarm`：当前可见 track 是否已有 `alarmed == true`；
- `reason`：`loitering`、`normal` 或 `unknown`；
- `updated_at_s`：快照时间。

现有 orchestrator 状态响应保留已有字段，并透传 `duration_seconds` 与 `threshold_seconds`。快照缺失或过期时人数、时长和阈值使用空值，告警为 false，不展示伪造数据。

视频在线状态继续以现有 JPEG 帧是否成功连接为准。FPS 继续读取现有摄像头字段，不新增推理性能接口。

## 告警与实时事件

今日告警次数继续读取现有 `getAlarms`，按 `detect_human`、当前摄像头和本地日期过滤；副文案显示最近一次告警时间，无记录时显示“今日暂无逗留告警”。

实时事件仅保存在浏览器内存中，不写数据库：

- 当前状态首次从正常变为超阈值时插入红色事件：“人员在区域内逗留 X 秒，触发告警”；
- 人员从区域内离开且该段停留未告警时插入灰色事件：“区域人数 X，停留 X 秒后离开，未告警”；
- 同一状态不重复插入；
- 切换摄像头时清空时间线；
- 列表最多保留 8 条。

人员离开、时长清零或快照过期后，人数胶囊恢复正常或中性状态，红色超时胶囊消失。

## 视频卡与覆盖层

`AiVisionMonitor` 增加 `human-dwell` 展示模式，但继续独占并保留现有摄像头加载、功能配置读取、200ms JPEG 帧轮询、请求超时、Blob URL 回收、页面可见性和图片原始尺寸处理。

人员逗留展示组件渲染：

- 标题“人员逗留检测监控”；
- 副标题为摄像头编号和点位名；
- 右上为区域人数、FPS、LIVE；
- 左上玻璃胶囊为实时检测、摄像头在线、区域人数，超阈值时增加红色“逗留超时告警”；
- 轻微暗角；
- 左下使用浏览器当前时间显示白色等宽时间戳；
- 右下显示画面状态小胶囊。

人员逗留模式不使用通用蓝色 ROI 覆盖层，而是用同一组现有 ROI 坐标绘制：

- `stroke: #22D3EE`；
- `fill: rgba(34,211,238,0.10)`；
- 标签为 `loitering_roi`，使用青色小牌；
- `viewBox` 使用现有帧坐标尺寸，`preserveAspectRatio="xMidYMid meet"`；
- 覆盖层均为 `pointer-events-none`。

不修改后端标注帧生成。若时间戳或 debug 已烧录在原始 JPEG 像素中，前端无法在不裁剪、不遮挡画面的前提下删除；本次只移除旧前端覆盖层并按新样式叠加。

## 组件边界

- `AiVisionMonitor`：保留摄像头、配置和视频帧生命周期；
- `HumanDwellMonitorView`：纯页面布局与覆盖层；
- `useHumanDwellMonitor`：串行轮询状态与告警，维护内存事件；
- `monitorState`：人数状态、事件转换和今日告警过滤的纯函数；
- `DwellDetectionConsumer`：发布只读展示快照。

物流单人检测和其他默认 `AiVisionMonitor` 页面不受影响。

## 验证

- 后端单元测试证明当前人数、最长时长、阈值和告警状态来自 tracker；
- 状态接口测试证明新字段透传且过期快照保持中性；
- 前端纯状态测试/契约覆盖超时、离开、去重、摄像头过滤和布局；
- 契约测试确认视频 URL、200ms 帧轮询、超时、Blob 回收及配置处理函数未改变；
- 运行相关 pytest、全部前端契约、生产构建、lint 和 `git diff --check`。

## 不在范围内

- 不改变检测阈值或跟踪算法；
- 不改变报警冷却、推送和入库；
- 不改变视频帧地址和轮询频率；
- 不持久化未告警的经过事件；
- 不通过 OCR 或图像分析反推前端数据。
