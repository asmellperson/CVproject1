# 管理员用户管理与账号数据库迁移设计

## 目标

把账号运行数据从受 Git 管理的 `auth/auth_users.json` 迁移到不进入
版本控制的 SQLite 数据库，并允许管理员在统一前端添加管理员或指定
事业部的普通用户。

生产服务器拉取新版 V4 后，不需要手工重写现有账号，也不需要编辑项目
配置文件。

## 数据存储与一次性迁移

默认数据库路径为：

```text
<项目根目录>/runtime/auth/auth_users.db
```

`runtime/` 已被 `.gitignore` 忽略。可通过 `AUTH_USERS_DB` 覆盖路径，但
默认部署不需要设置。

首次访问账号库时，在 SQLite 事务中创建用户表和迁移元数据表：

- 如果数据库尚未记录迁移完成，则读取当前服务器现有的
  `auth/auth_users.json`；
- 导入全部工号、姓名、角色、事业部、启用状态和已有密码哈希；
- 写入迁移完成标记后提交事务；
- 多个后端同时启动时由 SQLite 写锁串行完成初始化，不重复导入。

迁移完成后，登录、Token 用户复核、修改密码、用户列表和新增用户都只
读写 SQLite。后续启动只检查数据库迁移标记，不再打开或重新导入 JSON。
旧 JSON 在本次升级中保留为生产服务器首次迁移来源，但不再是运行数据。
如果首次迁移时 JSON 缺失、格式无效或包含重复工号/姓名，初始化会明确
报错且不写迁移完成标记，避免静默创建一个没有管理员的空账号库。

SQLite 使用 WAL、外键和 busy timeout，不新增第三方 Python 依赖。

## 用户模型与校验

数据库用户字段：

- `employee_id`：工号，必填且唯一；
- `name`：姓名，必填且唯一，因为当前登录允许工号或姓名；
- `role`：`admin` 或 `viewer`；
- `department`：事业部；
- `enabled`：是否允许登录；
- `password_hash`：PBKDF2-SHA256 密码哈希；
- 创建和更新时间。

管理员账号的事业部固定为 `all`。普通用户必须从以下五个事业部中选择：

- `general_electric`：通用电气事业部；
- `research_institute`：研究院；
- `electronics_electrician`：电子电工事业部；
- `electrical_components`：电气部件事业部；
- `precious_metal_recycling`：贵金属回收事业部。

管理员创建用户时直接设置至少 6 位的初始密码。后端只保存密码哈希，
前端和 API 响应绝不返回密码或哈希。新用户可以使用现有“修改密码”
功能自行更换密码。

本次范围只包含查看用户列表和新增用户，不提供删除、禁用、角色修改或
管理员重置密码，避免扩大高风险管理操作。

## 后端接口

统一后端增加两个仅管理员可访问的接口：

```text
GET  /api/admin/users
POST /api/admin/users
```

`GET` 返回安全字段组成的用户列表。`POST` 接收工号、姓名、角色、
事业部和初始密码，完成规范化、白名单校验、唯一性校验和密码哈希。

接口使用现有 `require_admin` 依赖执行服务端授权。普通用户即使绕过
前端直接请求，也会收到 HTTP 403。重复工号或姓名、无效角色/事业部、
短密码返回 HTTP 400，且不写入部分数据。

认证存储职责放在独立的 `auth/user_store.py`，现有 `auth/auth.py`
保留 JWT、Cookie 和认证编排，只通过存储接口访问用户，避免把数据库
逻辑堆入统一后端路由。

## 前端

增加仅管理员可见的“用户管理”导航项和页面：

- 页面加载时调用用户列表接口；
- 表格显示工号、姓名、角色、事业部和启用状态；
- “添加用户”对话框包含工号、姓名、角色、事业部、初始密码和确认密码；
- 角色选择管理员时事业部自动固定为“全部”；
- 普通用户必须选择一个事业部；
- 创建成功后关闭对话框、清空密码并刷新列表；
- 后端错误以中文提示显示，不把密码写入日志或 URL。

`user-management` 页面加入现有 `PageId` 权限体系。管理员可访问，普通
用户不可访问；即使手工修改 URL，也会回退到平台总览。

## 验证

后端测试覆盖：

- 现有 JSON 全字段一次性迁移；
- 迁移完成后修改 JSON 不影响数据库；
- 多次初始化不重复导入；
- 现有账号登录和修改密码继续工作；
- 新增管理员和五事业部用户；
- 重复工号/姓名、无效枚举、短密码拒绝；
- 普通用户访问管理接口返回 403；
- API 不泄露密码哈希。

前端测试与构建覆盖：

- `user-management` 仅管理员可访问；
- 表单角色与事业部联动；
- API 请求不包含确认密码；
- TypeScript、ESLint 和生产构建。

发布前执行差异和敏感信息检查。实际账号数据库及迁移后的内容不提交到
Git，远端 V4 只包含迁移代码、接口、页面和测试。
