# 项目前端一致性与 V4 发布规则设计

## 目标

在项目根目录 `AGENTS.md` 中固化两类项目级协作规则：前端修改优先对照既有检测功能，以及程序代码完成后自动发布到远程 `V4` 标签。

## 前端一致性规则

- 修改或新增前端页面、组件、交互或功能前，先查找并阅读项目中业务最相近的检测功能。
- 对照范围包括页面布局、组件结构、命名、状态管理、接口调用、加载与错误状态、权限控制和保存流程。
- 用户描述不完整时，默认沿用同类页面的既有模式，不自行增加按钮、弹窗、模式或新的交互层级。
- 优先复用共享组件和现有实现。若同类页面存在多个不同模式，或需求必须偏离现有模式，先向用户说明参考对象、差异和原因，得到确认后再实现。
- 修复问题时定位并修复根因，不用新增界面元素绕过已有错误。
- 完成说明中列出本次参考的同类页面或功能，以及保留一致和有意不同的部分。

## V4 自动发布规则

- 只有本次任务修改了程序代码并完成验证、创建本地提交后，才触发自动发布。
- 程序代码包括前后端源代码、可执行脚本和直接影响运行行为的代码文件；仅修改 `AGENTS.md`、Markdown 文档、设计规格、实现计划或说明性配置时不触发发布。
- 发布时不创建新分支：将本地 `V4` 标签强制指向当前 `HEAD`，再强制推送 `HEAD:refs/tags/V4` 到 `origin`。
- 推送后通过 `git ls-remote --tags origin refs/tags/V4` 校验远程标签提交必须与本地 `HEAD` 完全一致。
- 推送或校验失败时明确报告，不宣称发布完成；不得通过扩大提交范围或修改远程分支来规避失败。
- 提交和发布只包含当前任务范围内的程序代码，不夹带用户已有的无关工作区修改。

## 边界

- 本规则只作用于当前仓库，不写成全局 skill。
- 自动发布授权仅覆盖远程 `V4` 标签，不覆盖远程分支、其他标签、PR 或发布系统。
- 本次新增规则本身属于文档修改，因此不触发 `V4` 更新。
