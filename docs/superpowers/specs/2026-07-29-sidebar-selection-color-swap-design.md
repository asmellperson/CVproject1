# 导航栏父子选中配色交换设计

## 目标

交换侧边栏一级目录与二级检测功能当前使用的选中配色：

- 当前检测功能所属的一级目录显示深蓝渐变底色。
- 当前检测功能显示浅蓝底色。
- 未选中项目不显示选中底色。

## 现状

`unified_frontend/src/components/Sidebar.tsx` 已实现正确的父子选中状态：

- `childActive` 标识当前检测功能所属的一级目录。
- `active` 标识当前检测功能。

目前一级目录使用浅蓝底色，二级检测功能使用深蓝渐变。用户确认保留状态逻辑并严格交换这两套选中样式。

## 视觉设计

一级目录选中时使用当前二级检测功能的深蓝渐变、白色文字和较强阴影。一级目录箭头使用浅色，以保证深色背景下的对比度。

二级检测功能选中时使用当前一级目录的浅蓝背景、蓝色文字、淡蓝描边和轻阴影。检测功能图标与右侧箭头继承蓝色文字。

暗色模式同步交换对应样式：一级目录保留现有深蓝至青色渐变，二级检测功能使用半透明深蓝背景、浅色文字及深蓝描边。

未选中样式、悬停效果、字号、间距、展开和收起、菜单数据及权限逻辑均保持不变。

## 状态与数据流

不新增状态或组件：

1. `currentPage` 继续确定当前检测功能。
2. `activeChildGroupId` 继续确定所属一级目录。
3. `childActive` 控制一级目录深色选中样式。
4. `active` 控制二级检测功能浅色选中样式。

展开状态 `expanded` 仍只控制箭头旋转和子菜单显示，不参与选中配色。

## 修改范围

- 修改：`unified_frontend/src/components/Sidebar.tsx`
- 新增依赖：无
- 新增业务组件：无

## 验证

1. 运行修改前后样式契约检查，确认一级目录包含深蓝渐变选中类，二级检测功能包含浅蓝选中类。
2. 确认 `childActive`、`activeChildGroupId`、`active` 和 `expanded` 的用途不变。
3. 执行统一前端 `npm run build`。
4. 执行统一前端 `npm run lint`。
5. 人工确认一级目录为深色选中态、当前检测功能为浅色选中态，其他项目无选中底色。

## 风险

风险较低。修改仅交换现有配色。自动化检查可以确认类名和状态条件，最终颜色观感仍需在实际页面人工确认。
