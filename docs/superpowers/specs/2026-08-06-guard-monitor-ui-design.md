# 保安行为规范检测监控页 UI 重构设计

## 目标与边界

按照参考图重构“保安行为规范检测”页面的视觉层级和响应式布局。只调整 React 展示结构和 Tailwind 样式，不修改接口路径、请求参数、轮询频率、响应字段、启停逻辑、刷新逻辑、权限判断或帧图片播放方式。

监控画面是三路摄像头拼接后的完整帧，前端必须尊重图片固有比例。禁止使用 `aspect-video`、固定视频高度、`object-cover` 或其他 16:9 假设；帧图片始终使用 `block h-auto w-full` 完整显示。

## 页面结构

### 标题与标签页

`GuardBehaviorSection` 负责页面标题和分段标签页：

- 通用电气页面标题为“通用电气保安行为规范监控与配置”。
- 电子电工页面使用对应事业部名称，避免共用组件出现错误标题。
- 副标题固定为“行为分析监控面板”，不拼接保安室名称。
- “实时监控 / 配置管理”使用白色圆角分段控件；选中项使用 `#132C72` 深蓝底和白字。

页面背景使用 `#F3F5FA`。卡片统一使用白底、`rounded-2xl`、半透明 slate 边框和轻阴影。

### 顶部统计卡

实时监控内容顶部展示四张响应式统计卡：

- 摄像头状态：根据现有 `status.running`、`status.error` 和帧图可用状态显示在线或离线。当前接口不能区分拼接画面的三路源，因此不伪造“在线 3/3”。
- 在岗人数：使用 `status.counts.persons`；识别置信度使用 `status.metrics.person_confidence`。
- 检测帧率：使用 `status.fps`；副文案显示“推理延迟约 154ms”。
- 异常行为：统计 `status.decisions.phone_use`、`prone_sleep`、`vehicle_unattended` 中为真的数量；全部为假时显示“0 项”。

所有字段只读展示，不改变数据类型或状态来源。

### 主体布局

统计卡下使用 `grid lg:grid-cols-3 gap-5`：

- 左列使用 `space-y-5` 排列“监控对象”“检测控制”“实时检测项”。
- 视频流卡片使用 `lg:col-span-2`。
- 拼接帧较高时允许视频卡自然增高，左列不拉伸视频、不制造等高裁剪。

“检测详情”和“最近报警”保留在主体布局下方，并统一卡片样式，避免删除现有信息展示。

## 左列卡片

### 监控对象

保留现有站点列表、`selectedSiteId` 和 `onSelectSite` 绑定。Radix Select 使用浅灰背景、圆角边框和深蓝 focus 状态；不替换选择组件或改变选值类型。

### 检测控制

运行徽章由 `status.running` 驱动。启停按钮继续调用原 `handleStartStop`，刷新按钮继续调用原 `handleRefresh`；管理员权限、busy 和无站点禁用条件保持不变。按钮改为两列实心/浅色状态样式，刷新图标使用点击态旋转反馈，不增加网络请求。

### 实时检测项

展示四项：

- 手机使用检测：`status.decisions.phone_use`。
- 俯卧姿态检测：`status.decisions.prone_sleep`。
- 车辆入侵检测：`status.decisions.vehicle_unattended`。
- 保安在岗识别：`status.counts.persons` 是否大于零。

前三项 false 为绿色“正常”，true 为玫红色“异常”；在岗人数为零时显示琥珀色“未在岗”。

## 视频卡片

卡片头部显示视频图标、标题、`cam1 · 站点名`、FPS 和 LIVE/已暂停状态。视频区保持 `relative overflow-hidden bg-slate-900`，图片使用 `block h-auto w-full` 和轻微降饱和滤镜，不裁剪、不拉伸。

前端覆盖层包括：

- 左上角可换行状态胶囊：cam1 在线状态、在岗人数、手机、俯卧和车辆状态。
- 不拦截事件的轻微上下暗角。
- 右下角静态“1080P · H.265”视觉胶囊。
- 检测关闭时的半透明灰度遮罩、Pause 图标和恢复提示。
- 后端错误时继续显示现有错误信息。

当前 `BackendStatus` 不包含 ROI 点、单路尺寸、拼接方向或整帧尺寸。黄色 ROI 和时间戳已由后端绘制进帧图片，因此前端保留其原样，不新增伪造 SVG、不重复时间戳，也不改变 ROI 坐标逻辑。

## 组件边界

`GuardBehaviorSection` 只负责标题、标签页和现有站点管理状态。`MonitorSection` 保留所有请求和控制逻辑，新增同文件内或独立展示组件用于统计卡、检测状态行和视频状态胶囊，减少主 JSX 重复；展示组件不发请求、不持有业务状态。

## 验证

- 契约测试确认原接口调用、轮询、启停、刷新和字段绑定仍存在。
- 契约测试确认帧图片使用 `h-auto w-full`，并禁止 `aspect-video`、`object-cover` 和固定 16:9 容器。
- 契约测试确认四张统计卡、三张左栏卡、视频状态胶囊和暂停遮罩存在。
- 运行全部前端契约测试、生产构建和 lint。

## 风险

无法仅靠当前前端接口精确显示三路各自在线数量、客户端 ROI 或重新绘制时间戳。此次明确不伪造这些信息；若以后后端提供拼接元数据，再单独设计客户端坐标映射。
