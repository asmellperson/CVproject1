# AiVision 实时监控旧帧恢复设计

## 背景

正式环境的“物流通道单人检测”实时监控停留在最后一张图片，但页面仍显示“实时画面已连接”。线上前端会每 200ms 请求一次 `frame.jpg`，并在每次收到成功响应后显示已连接。

后端当前优先返回检测功能生成的标注帧。当摄像头原始帧已经不存在时，只要 Consumer 中还保存着历史标注帧，接口就会忽略该标注帧的更新时间并持续返回它。相同的更新时间还会命中 JPEG 缓存，因此客户端不断收到同一张图片和 `200 OK`。

前端在帧请求失败时不会清除上一张图片，请求本身也没有超时。这会进一步把断流表现成“画面冻结”。此外，当前 5 FPS 预览请求没有尺寸限制，高分辨率摄像头会增加后端编码、网络传输和浏览器解码负担。

## 目标

- 仅在标注帧足够新时返回标注帧。
- 标注帧过期后，在原始帧仍新鲜时回退到原始帧。
- 原始帧与标注帧都不可用或过期时返回明确的不可用响应。
- 前端帧请求超时或失败后不再保留误导性的旧图片。
- 限制实时预览分辨率，保持现有 5 FPS 刷新节奏。

## 非目标

- 不修改物流通道单人检测的识别、告警和工作时间逻辑。
- 不重构摄像头进程、共享内存或推理调度架构。
- 不修改正式服务器部署配置或直接部署本次代码。

## 方案

### 后端帧选择

在 `Orchestrator.get_camera_frame_info` 中分别判断原始帧和标注帧的新鲜度：

- 标注帧存在且更新时间不超过 2 秒时，优先返回标注帧。
- 标注帧不存在或已经过期，但原始帧更新时间不超过 10 秒时，返回原始帧。
- 两者都不新鲜时返回 `None` 及最近一次已知更新时间，由现有 API 转换为 `503 camera frame is stale`；从未产生过任何帧时维持现有 `404 frame not available` 语义。

原始帧是否存在不再允许绕过标注帧的过期检查。

### 前端监控恢复

在 `AiVisionMonitor` 的单次帧请求外增加固定超时。超时通过已有 `AbortController` 中止，并进入统一失败路径。

帧请求失败时：

- 撤销并清除当前 object URL；
- 清空 `frameSrc`，不再显示最后一张旧图片；
- 显示现有的画面读取失败提示；
- 保留后续轮询，使摄像头恢复后页面可以自动重新连接。

实时预览请求重新传入 `maxWidth: 960`，后端继续按已有参数缩放 JPEG。ROI 使用图片实际尺寸构建 `viewBox`，缩放后的坐标展示逻辑保持一致。

## 测试设计

后端回归测试覆盖：

- 原始帧缺失且标注帧过期时不得返回旧标注帧。
- 新鲜标注帧优先于新鲜原始帧。
- 标注帧过期时回退到新鲜原始帧。
- 原始帧和标注帧都过期时返回不可用结果。

前端测试把帧加载的超时、失败清理和预览参数提取为小型可测试单元，覆盖：

- 预览 URL 包含 `max_width=960` 与既有质量参数。
- 超时会中止请求。
- 失败路径会清除旧 object URL 和画面状态。

最后运行 AiVision 最小回归测试、前端相关测试、TypeScript 构建。

## 风险与兼容性

- 摄像头短暂抖动超过 10 秒后，页面会明确显示断流而不是旧图；这是预期行为变化。
- 960px 预览会减少细节，但只影响监控预览，不影响原始帧上的模型推理、告警截图或 ROI 配置数据。
- 修复不会主动重启摄像头；正式环境若持续断流，仍需根据运行状态和日志处理 RTSP 或采集进程问题。
